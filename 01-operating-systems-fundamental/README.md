## 💻 مقدمه ای بر سیستم عامل
سیستم‌ عامل **(Operating System)** یک نرم‌ افزار سیستمی است که وظیفه‌ی اصلی آن **مدیریت منابع سخت‌ افزاری و فراهم‌ کردن محیطی برای اجرای برنامه‌ ها و تعامل کاربران با سیستم** است. سیستم‌ عامل را می‌ توان یک **لایه‌ ی نرم‌افزاری واسط بین Hardware و Applications و Users** در نظر گرفت ، به‌ طور کلی :

<img width="100%" height="576" alt="image" src="https://github.com/user-attachments/assets/fbf2b2b1-12ef-43a5-a4c4-2ec3ceb2cc4d" />

سیستم‌عامل از یک طرف با **Hardware** و منابع سیستم سروکار دارد و از طرف دیگر خدمات مورد نیاز **Applications** و **Users** را فراهم می‌ کند. سخت‌افزار سیستم شامل منابع مختلفی مانند **CPU و Memory و Storage و I/O Devices** است که سیستم‌ عامل وظیفه‌ ی مدیریت و تخصیص آن‌ ها را بر عهده دارد.

###  چرا به سیستم‌ عامل نیاز داریم ؟

کار کردن مستقیم با منابع سخت‌ افزاری برای کاربران و برنامه‌ های کاربردی پیچیده است. برای مثال ، یک Application برای استفاده از دیسک نباید مجبور باشد جزئیات فنی کنترلر دیسک ، نحوه‌ ی ارتباط با Hardware و تمام جزئیات مربوط به آن را بداند. سیستم‌ عامل این پیچیدگی را مدیریت می‌ کند و یک Interface مناسب در اختیار برنامه‌ ها و کاربران قرار می‌ دهد. به همین دلیل می‌ توان گفت سیستم‌ عامل بین نیازهای Applications و Users و پیچیدگی Hardware قرار می‌ گیرد.

####  1️⃣ سیستم‌ عامل به‌ عنوان یک واسطه 

در لایه Applications و Users برای استفاده از منابع سیستم ، درخواست خود را از طریق Interface های فراهم‌ شده توسط سیستم‌ عامل مطرح می‌ کنند. سیستم‌ عامل این درخواست‌ ها را مدیریت کرده و در صورت وجود مجوز و منابع کافی ، عملیات موردنظر را انجام می‌ دهد ، برای مثال :

```
Application
     |
     | Request
     v
Operating System
     |
     | Manage / Control
     v
Hardware Resource
```

این موضوع باعث می‌ شود Application ها بتوانند از منابع سیستم استفاده کنند ، بدون اینکه نیاز داشته باشند جزئیات پیچیده‌ ی Hardware را مستقیماً مدیریت کنند.

#### 🔌 تعریف Device Driver :

نرم‌ افزاری است که به سیستم‌ عامل کمک می‌ کند با یک سخت‌ افزار خاص ارتباط برقرار کند. هر Hardware ممکن است روش و Interface متفاوتی برای کنترل داشته باشد. Driver این جزئیات را برای سیستم‌ عامل فراهم می‌ کند تا سیستم‌ عامل بتواند از آن Hardware استفاده کند ، به‌ عنوان مثال :

```
Operating System
       |
       v
Device Driver
       |
       v
Hardware Device
```

درایورها معمولاً توسط سازنده‌ ی Hardware یا پروژه‌ های مرتبط با سیستم‌ عامل توسعه داده می‌ شوند و ممکن است در قالب‌ های مختلفی در سیستم‌ عامل قرار بگیرند.

#### 2️⃣ مدیریت بهینه‌ ی منابع (Resource Management)

یکی از مهم‌ ترین وظایف سیستم‌عامل ، **مدیریت منابع سیستم** است ، منابعی مانند :

- CPU
- Memory
- Disk / Storage
- Network
- Input / Output Devices

باید بین برنامه‌ ها و کاربران مختلف مدیریت و تخصیص داده شوند. برای مثال ، زمانی که چند Application به‌ طور هم‌ زمان در حال اجرا هستند ، سیستم‌عامل باید مشخص کند :

- چه پردازشی چه مقدار CPU دریافت کند ؟
- چه مقدار Memory به هر Process اختصاص داده شود ؟
- دسترسی به Storage چگونه مدیریت شود ؟
- درخواست‌ های I/O با چه ترتیبی انجام شوند ؟

هدف سیستم‌ عامل این است که منابع موجود را به شکل **مناسب و کارآمد** مدیریت کند.

#### 3️⃣ مدیریت نیاز های Users و Applications


سیستم‌ عامل باید درخواست‌ های مختلف کاربران و Application ها را مدیریت کند. از آنجا که ممکن است چندین Process به‌ طور هم‌ زمان به یک Resource نیاز داشته باشند ، سیستم‌عامل باید بر اساس سیاست‌ ها و الگوریتم‌ های مشخص تصمیم بگیرد که منابع چگونه تخصیص داده شوند. برای مثال ، در مورد CPU ، سیستم‌عامل از **CPU Scheduling** استفاده می‌ کند تا مشخص شود Process ها چه زمانی و چه مقدار از CPU را در اختیار داشته باشند. بنابراین سیستم‌ عامل علاوه بر مدیریت Hardware ، وظیفه‌ ی مدیریت هم‌ زمانی و استفاده‌ ی مشترک چندین Application و User از منابع سیستم را نیز بر عهده دارد.

```
Process A ─┐
Process B ─┼──> CPU Scheduler ──> CPU
Process C ─┤
Process D ─┘
```

### 🐧 سیستم‌ عامل Linux

لینوکس یک سیستم‌ عامل مبتنی بر معماری Unix-like است که هسته‌ ی آن**Linux Kernel** نام دارد. Kernel مهم‌ ترین بخش سیستم‌عامل است و وظیفه‌ ی مدیریت منابع سیستم و فراهم‌ کردن ارتباط بین نرم‌ افزار و Hardware را بر عهده دارد. به‌ صورت ساده می‌ توان معماری Linux را این‌ گونه در نظر گرفت :

#### 🧠 کرنل لینوکس

کرنل هسته‌ ی سیستم‌عامل است و مسئولیت‌ هایی مانند موارد زیر را بر عهده دارد و Application ها معمولاً برای درخواست سرویس از Kernel از طریق**System Call** با آن ارتباط برقرار می‌ کنند :

- مدیریت CPU
- مدیریت Memory
- مدیریت Process ها
- مدیریت Device ها
- مدیریت File System ها
- مدیریت Network
- فراهم‌ کردن System Call ها

#### 💻 تعریف Shell : 

یک برنامه‌ ی User Space است که امکان تعامل کاربر با سیستم‌ عامل را فراهم می‌ کند. در محیط Linux می‌ توان از Shell برای اجرای دستورات و اجرای برنامه‌ ها استفاده کرد ، برای مثال :

```
ls
cd /var/log
pwd
cat /etc/os-release
```

یکی از معروف‌ ترین Shell ها در لینوکس Bash است. Shell می‌ تواند یک محیط CLI (Command-Line Interface) در اختیار کاربر قرار دهد همچنین کاربران می‌ توانند از محیط‌ های گرافیکی مانند GUI برای تعامل با سیستم استفاده کنند. نکته مهم این است که Shell مستقیماً جایگزین Kernel نیست بلکه یک برنامه‌ ی User Space است که برای اجرای عملیات ، از  Interface های سیستم‌ عامل و در نهایت System Call ها استفاده می‌ کند.

#### 📁 همه چیز یک فایل است !

در Linux و سیستم‌ های Unix-like ، بسیاری از منابع سیستم از طریق Interface هایی شبیه فایل در اختیار کاربران و برنامه‌ ها قرار می‌ گیرند برای مثال Device ها در مسیر```dev/```  قابل مشاهده هستند. همچنین اطلاعات مختلف مربوط به Kernel و Process ها از طریق فایل‌ سیستم‌ های مجازی مانند ```proc/``` و ```sys/``` در اختیار سیستم قرار می‌ گیرند ، به همین دلیل در Linux با مفهوم معروف **Everything is a file** مواجه می‌ شویم. البته این عبارت یک ساده‌ سازی مفهومی است و به این معنی نیست که واقعاً تمام اجزای سیستم یک فایل معمولی هستند.
